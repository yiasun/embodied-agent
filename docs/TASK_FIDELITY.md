# 任务忠实性修复：有边界的顺序导航契约

## 问题与修复

旧链路只检查模型输出是否合法，未验证是否完整表达用户任务。
因此“先去A区，再去C区”可能被模型缩减为合法的A区步骤，并被标记为READY。

现在Agent先在本地完整解析指令，再检查每个地点。未知地点会在Provider构造和模型请求前被拒绝。
模型返回后，Intent Validator必须同时接收原始指令导出的期望地点序列；Schema、动作、地点检查通过后，再做完整列表相等比较。
只有地点、顺序、次数全部一致，才允许调用build_plan并产生READY。
不使用集合比较、不忽略重复地点、不接受部分成功、不让模型解释或重写期望序列。

## 可验证范围：explicit-navigation-v1

这是受限的、可验证的导航命令语言，不是通用语义理解器。

- 每个子句只能有一个导航动作：去、前往、到达、到。
- 子句使用逗号、顿号或分号分隔；允许一个句尾句号。
- 可以使用先、再、然后、接着、最后等标记，但它们必须与子句位置一致。
- 地点必须精确匹配当前注册表，不假设A/B、不要求“区”后缀。
- 一条指令1—20步；明确重复的地点表示多次访问，必须逐项保留。
- 裸地点名只允许字母、数字、下划线、连字符，且不得包含语法保留词。
- 包含空格、分隔符或保留词的合法地点名，可以用双引号、中文双引号或「」明确标记为字面量。
- 引号里的名字仍必须匹配注册表；引号不允许绕过未知地点检查。

示例（地点已在注册表中时）：

```text
先去A区，再去B区
去A区，去A区
先去取件点，再去充电站，最后去取件点
去「不夜城」
```

以下均停止规划，不发送请求，不推断、不删除不支持部分：

```text
不要去A区
去A区，等待5秒
去A区两次
如果A区有人就去B区
去A区或B区
先去那里，再去B区
先去A区然后去B区
```

当前不解析无分隔符连写、否定、条件、代词、别名、次数展开、混合动作、隐含返回、相对方位或上下文引用。
对于这些输入，用户应重新给出明确、完整的导航子句；系统不会向LLM请求“猜测正确意图”。
裸名中的否定和连接词可能与真实地名冲突，故保守拒绝，必要时要求显式引用字面地名。
这属于公开的语法限制，不代表已实现一般中文语义判断。

## 错误与接口

- 明确但未注册的地点：UNKNOWN_LOCATION，调用模型前拒绝。
- 语法超出范围或需要澄清：沿用RULE_PARSE_ERROR，不论选择哪个Provider。
- 指令任务数越界：INVALID_TASK_COUNT。
- 模型步骤序列不忠实：TASK_FIDELITY_MISMATCH。
- 模型非法动作/结构仍沿用ILLEGAL_ACTION、INVALID_INTENT_SCHEMA等既有错误码。

CLI参数保持不变；没有新执行开关，也不自动控制机器人。
内部validate_intent现在必须显式传入expected_locations，不能只做结构校验后当成已验证意图。
低层ProviderResult仍是未被接受的原始响应，不是READY计划；完整接受边界位于plan_instruction。

Qwen/Ollama直接调用generate_intent时也会进行输入预检查，防止绕过Agent后为已知无效任务发起请求。
Prompt明确禁止删步、去重、调序、增加或替换步骤，并包含本地验证过的完整期望序列（只有动作和地名，没有坐标）。
Prompt只是辅助约束；真正的验收仍是本地精确比较。
Rule Provider复用同一个导航契约。旧nl_parser_v1独立实验CLI保留，未被当成新Agent的通用语义模块。

成功保存的provenance新增faithfulness：语法版本、完整期望地点列表及verified=true。
原指令与计划的SHA-256追踪、密钥脱敏和V4安全执行链路保持不变。
任何解析或忠实性错误都不会导出新的READY计划文件。

测试覆盖原问题、调用前未知地点、遗漏、替换、顺序错误、额外重复、重复访问被去重、否定、额外动作、含糊输入、自定义地名及失败时不导出计划。

```bash
cd ~/embodied-agent
PYTHONDONTWRITEBYTECODE=1 python3 -B -m pytest -q -p no:cacheprovider
```

没有真实API请求、导航目标或历史实验数据变更。
未来扩展复杂任务时，需要独立的语义/任务图契约、消歧或用户确认机制，并新增对应的完整性验证；不能关闭当前校验让LLM自由裁剪任务。
该检查只证明在本语法下的任务序列忠实性，不证明地图标注正确、地点可达或实际执行成功。
已导出的历史计划不带新的忠实性证明，本次没有重写或重新认证它们；旧计划不能被当作修复后的验证结果。
